I got tired of losing track of what my AI agent actually *did* during a long session, so I built `obsidian-chat-summary`. It’s a small skill that turns a messy terminal history into a clean, structured Markdown note for your Obsidian vault.

The goal is simple: make AI interactions searchable and permanent without manual copy-pasting or spending time formulating what you care to remember or the formatting and style you'd like to maintain.

## How it works

The skill doesn't just dump text; it filters for the technical signal that actually matters.

### 1. The Checkpoint Habit
Hooks into the `/chat save` command. Before it even starts writing a summary, the skill generates a timestamp tag (like `summary-20260220-153000`) and makes sure you’ve saved the session state. If you ever need to jump back in, you have the exact state and the summary side-by-side.

### 2. High-Signal Harvesting
Instead of conversational fluff, the logic hunts for:
- **Code Deltas:** What actually changed in the files?
- **Decision Log:** Why did we pick *this* architectural path over that one?
- **Open Loops:** What's still broken or left todo for the next session?

### 3. GitOps Verification (Advanced)
In a professional setup, documentation should be verifiable. By using this skill within a **Hub & Spoke** architecture (where skills are managed as Git submodules), every summary and log entry can be tethered to a specific Git SHA. 

This means your Obsidian vault doesn't just say "I fixed the bug"; it says "I fixed the bug at `[ref: 8c6f634]`." This creates a verifiable trail of evidence for every change in your knowledge base.

### 4. Centralized Shared Settings (DRY)

The skill pulls from a central configuration at `_shared-gemini/` to get info and configs that are relevant to multiple skills (like the upcoming `conversation-flow`), like formatting that matches my Obsidian vault style.

```markdown
# Shared frontmatter and style template
---
tags:
  - ai_text
  - {{tags}}
date_created: {{date}}
---
# Contextual identifiers
- **Working Directory:** `{{working_directory}}`
- **Operating System:** `{{os}}`
```

#### ai_text tagging

I’ve made it a point to add a mandatory `ai_text` tag to every note generated by the agent. This is essential to separate out my thoughts and writing from ai genarated notes when reviewing the vault in the future.

> [!IMPORTANT] Directory Structure Requirement
> By default, this skill expects the `_shared-gemini` folder to be a **sibling** of the skill directory (it looks for `../_shared-gemini/skill_settings.md`). 
> 
> If you choose to place your shared settings elsewhere, you will need to open the `SKILL.md` file and update the path in Step 1 of the "Workflow" section to match your custom location.

## Try it out

### 1. Get the Shared Config
Clone the base settings into your project root:

```bash
# Clone the public repository
git clone https://github.com/ReutFarkash/gemini-skills.git
```

### 2. Install the Skill
If you’re using the Gemini CLI, you can pull this in directly:

```bash
gemini skill install https://github.com/ReutFarkash/gemini-skills/blob/main/obsidian-chat-summary/SKILL.md --scope user
```

### 3. Run with Context
Launch your session including the shared directory:

```bash
gemini --include-directories /path/to/gemini-skills/_shared-gemini
```

Once it's in, just run ask the chat to use `obsidian-chat-summary` at the end of a task.
